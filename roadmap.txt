## Roadmap par étapes

### Étape 1 — Setup MLX & fenêtre *(2-3h)*
- Init MLX, ouvrir une fenêtre 1280×720
- Créer une image buffer (`mlx_new_image`) → **tout le rendu se fait dans ce buffer**, jamais directement dans la fenêtre
- Hook sur ESC + croix rouge → exit propre
- `mlx_loop` qui tourne

> **Pourquoi le buffer ?** C'est bien plus rapide que de dessiner pixel par pixel dans la fenêtre. Tu génères l'image en RAM puis tu fais `mlx_put_image_to_window` une fois par frame.

---

### Étape 2 — Raycaster de base *(3-4 jours)*

C'est le gros morceau. La logique en 4 sous-étapes :

**2a — Comprendre la théorie** (indispensable avant de coder)
Lis le tutorial de Lode Vandevenne : **https://lodev.org/cgtutor/raycasting.html** — c'est LA référence, tout y est expliqué avec des schémas.

**2b — Calculer les rayons**
Pour chaque colonne de pixel (de 0 à WIDTH) :
- Calcule la direction du rayon depuis la position du player
- Lance le DDA (Digital Differential Analysis) pour trouver le premier mur touché
- Calcule la distance perpendiculaire au plan caméra (évite l'effet fish-eye)

**2c — Calculer la hauteur du mur**
- `line_height = HEIGHT / perp_wall_dist`
- `draw_start` et `draw_end` = où commencer/finir de dessiner la colonne

**2d — Couleurs simples d'abord**
Avant les textures : affiche les murs en couleur unie (rouge/vert selon la side), le sol d'une couleur, le plafond d'une autre. Valide que le rendu est correct.

---

### Étape 3 — Textures *(1-2 jours)*
- Charge les 4 textures XPM avec `mlx_xpm_file_to_image`
- Calcule le `wall_x` (où exactement le rayon a touché le mur, en 0.0-1.0)
- Déduis le `tex_x` (colonne dans la texture)
- Pour chaque pixel de la colonne, calcule le `tex_y` et récupère la couleur via l'adresse de l'image texture

---

### Étape 4 — Mouvements & collisions *(1 jour)*
- Hooks clavier : W/A/S/D pour bouger, flèches pour tourner
- Rotation = multiplier dir et plane par une matrice de rotation
- Collision : avant de déplacer, vérifie que la case cible est `0` dans la map (ou une porte ouverte)

**Bonus wall collision** : au lieu d'un check binaire, donne une marge (`player_radius ~0.2`) pour ne pas coller les murs.

---

### Étape 5 — Minimap *(bonus, ~1 jour)*
Dessine dans un coin de l'écran (en haut à gauche par exemple) :
- La map en petit (chaque case = 8×8 pixels)
- Le player comme un point coloré
- Les rayons ou juste le cône de vision (optionnel)

Fais ça après le raycaster, c'est purement 2D et assez rapide à faire.

---

### Étape 6 — Portes *(bonus, 1-2 jours)*
- Ajoute un caractère `D` dans la map pour les portes
- Une porte a un état : `0` (fermée/mur) ou `1` (ouverte/passable)
- Touche E (par exemple) = si le joueur est face à une porte à distance ≤ 1.5, toggle l'état
- Dans le raycaster : si `side == door` → texture de porte spécifique
- Animation possible : interpoler la porte qui s'ouvre sur quelques frames

---

### Étape 7 — Mouse rotation *(bonus, ~2h)*
- `mlx_hook` sur `MotionNotify` pour récupérer la position souris
- Delta X souris → ajouter à la rotation du player
- Pense à re-centrer la souris chaque frame pour éviter qu'elle sorte de la fenêtre (`mlx_mouse_move`)

---

### Étape 8 — Sprites animés *(bonus, le plus complexe)*
Les sprites sont des objets 2D qui se font toujours face au joueur (billboarding) :
- Stocke une liste de sprites avec position dans la map
- Trie-les par distance (les plus loin en premier, Z-buffer)
- Pour chaque sprite : calcule sa position à l'écran, sa taille, et dessine seulement les pixels non cachés par des murs (utilise le Z-buffer calculé pendant le raycasting)
- Animation : cycle entre plusieurs textures avec un timer (gettimeofday)

---
